# Bandage 웹 프로토타입 vs 현재 코드베이스 차이 분석

## 📊 종합 요약

| 영역         | 프로토타입                   | 코드베이스                                                             | 상태          |
| ---------- | ----------------------- | ----------------------------------------------------------------- | ----------- |
| **밴드 탐색**  | 사이드 패널 목록 + 검색/필터 UI    | 목록만 있음, **검색 UI 없음**                                              | ⚠️ 부분 누락    |
| **밴드 상세**  | 좌측 목록 + 우측 상세 (마스터-디테일) | `page.tsx`에서 `EmptyPane`만, 실제 상세는 `/bands/[bandId]`로 **풀 페이지 이동** | ⚠️ 레이아웃 불일치 |
| **탭 구조**   | 개요 / 멤버 / 가입 신청         | 동일 (`overview / members / applications`)                          | ✅ 일치        |
| **홈 대시보드** | 통계 4카드 + 2열 그리드         | 존재 (`HomeStatCards`, `MyBands`, `UpcomingPractices/Performances`) | ✅ 일치        |

---

## 🔴 주요 누락 요소

### 1. 밴드 탐색 (Discovery) — 거의 전부 없음

**프로토타입에 있던 것:**

- 상단 검색 바 (밴드명/설명 검색)
- 장르/활동 상태 필터 칩
- 내가 속한 밴드 ↔ 전체 밴드 구분
- 추천 밴드 섹션

**코드베이스 현황:**

- `BandsList` — 단순 무한스크롤 목록만 (`getBands`에 `lastId`, `pageSize`만 있음)
- `BandsListPane` — 사이드 패널에도 **검색 입력 없음**
- "참여 중인 밴드가 없습니다" 빈 상태만 존재
- **타 밴드 탐색/검색 API 자체 미구현** (`/api/v1/bands`는 단순 커서 목록)

### 2. 밴드 상세 — 레이아웃 불일치

**프로토타입:** 좌측 목록 패널 + 우측 상세가 **한 화면 동시** 표시 (마스터-디테일)

**코드베이스:**

- `/bands` 데스크톱 뷰 = `EmptyPane`("밴드를 선택해 주세요")만 표시
- `/bands/[bandId]` = 풀 페이지로 이동 → **목록 패널이 사라짐**
- `BandsListPane`은 layout에 있지만, 상세 진입 시 함께 보이는지 확인 필요

### 3. 밴드 상세 내 세부 요소 누락

|프로토타입 요소|코드 상태|
|---|---|
|프로필 이미지 업로드/편집|❌ 읽기 전용 (`profileImg` 표시만)|
|밴드 정보 편집 (이름/설명)|❌ 없음 — 수정 API·화면 미구현|
|멤버 역할 변경 UI|⚠️ `delegateLeader` API만 존재, 리더 → 관리자/멤버 강등 UI 없음|
|멤버 강퇴|❌ API/UI 없음|
|장르·활동지역·결성일 등 메타|❌ `BandInfoResponse`에 필드 자체 없음 (`bandName/description/profileImg`만)|
|활동 로그/피드|❌ 전혀 없음|

### 4. 가입 신청 관련 누락

- `BandApplicationInfoResponse`에 **신청자 이름/프로필** 없음 — `memberId`만 있음
- 신청 시 메시지(자기소개) 입력 UI: ❌
- 거절 사유 입력: ❌

### 5. 합주(Practice) 탭 분리 안 됨

**프로토타입:** 상세 화면 내 `세션 / 참가자 / 곡·링크` 탭 분리

**코드베이스:** `PracticeDetailContent`에서 모든 섹션을 **수직으로 나열** (Card로 구분만)

- 탭 컴포넌트(`Tabs`)는 있지만 사용 안 함
- 긴 스크롤로 정보 탐색 어려움

### 6. 공연(Performance) 상세 누락 기능

- 공연-합주 연결 UI는 있지만, 프로토타입의 **"참여 밴드 pill 목록"** 은 확인 필요
- 공연 포스터/이미지 업로드: ❌
- 티켓 링크, 장소 지도: ❌

### 7. 프로필/마이페이지 차이

| 프로토타입                   | 코드베이스        |
| ----------------------- | ------------ |
| 프로필 사진 + 카메라 아이콘        | ❌ 아바타 업로드 없음 |
| 프로필 카드 2열 그리드 (정보 / 설정) | ⚠️ 단일 컬럼     |
| "내 밴드", "참여 공연" 통계      | ❌ 없음         |
| 알림 설정                   | ❌ 없음         |

## 🟡 구조적 차이

### A. 반응형 전략

- 코드베이스는 **모바일 우선** (`lg:hidden` / `hidden lg:block` 분기)
- 프로토타입은 데스크톱 단일 레이아웃
- → 데스크톱 마스터-디테일이 **레이아웃 레벨**(`bands/layout.tsx`)에서 구현되어야 하는데 `page.tsx` 수준에서만 분기 중

### B. 네비게이션 패러다임

- 프로토타입: SPA 내부 state로 패널 전환 (URL 고정)
- 코드베이스: Next.js 라우팅 (`/bands` → `/bands/[bandId]` 이동)
- → 상세 진입 시 목록 스크롤 위치 소실 가능

### C. 도메인 타입 빈약

`BandInfoResponse` 필드가 `bandId / bandName / description? / profileImg?` 4개뿐 — 프로토타입의 풍부한 밴드 카드를 만들려면 백엔드 스키마 확장 필요 (장르, 멤버 수, 활동 지역 등).

## 📋 우선순위 보완 제안

**P0 (필수)**

1. 밴드 탐색 검색 UI + `getBands`에 `query/genre/status` 파라미터 추가
2. 데스크톱 마스터-디테일을 `bands/layout.tsx`에서 구현 (상세 진입 시에도 목록 유지)
3. 밴드 정보 편집 API/화면
4. 합주 상세 탭 분리 (Tabs 적용)

**P1 (중요)** 5. 멤버 강퇴/역할 변경 UI 6. `BandInfoResponse` 스키마 확장 (장르·지역·멤버 수) 7. 프로필 이미지 업로드 8. 가입 신청 메시지/거절 사유

**P2 (개선)** 9. 공연 포스터 업로드, 티켓 링크 10. 마이페이지 통계 카드 11. 알림 설정
- 현재는 구현X(추후 MVP2차 과업으로 별도 진행)
